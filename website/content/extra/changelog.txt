==== 2026-10-09 - DocFetcher 2.10 ====

=== Bugfixes ===
  * AI assistants asked for permission to file paths in every conversation (Claude Desktop with file access tried to open the documents itself, and could stop when the request was rejected): the MCP server gives short ids instead of paths - with the name and the folder inside the indexed folders - and all tools take the ids. get_original_document is only meant for when the original itself is needed; for the content read_document. The folder for files from assistants is no longer named in advance: get_file_folder asks the user first ('Remember my choice'; 'Reset Remembered Answers' asks again).
  * The options for AI assistants have their own tab 'AI Assistants (MCP)'; options that need the MCP server are indented below it and disabled while it is off.
  * After a package was replaced, DocFetcher could ask whether to delete 'incompatible index files' such as an empty folder 'inbox_<number>': a leftover of a deleted index whose folder Windows couldn't remove at once, taken for an index of DocFetcher 1.0.3. Empty leftovers are now removed quietly, and a folder created while DocFetcher runs (an index being built) is never reported.

=== Features ===
  * Assistants with their own file access (e.g. Claude Code) can save new files for the user: in the preferences (tab 'AI Assistants (MCP)') the user chooses one of the inbox folders (none by default). The MCP tool get_file_folder and the server instructions tell the assistant the folder and the rule to only add new files there - never change, overwrite, rename, move or delete; without permission yet, it asks the user for access to exactly this folder. DocFetcher indexes the new files; it writes nothing itself. (Ways through DocFetcher - files from table rows or text, downloads, base64 - were tried during 2.10 and dropped: assistants without file access can't hand over real files.)
  * MCP tool show_document: AI assistants can show documents to the user in DocFetcher ('show me the rental contract'). The window comes to the front (also from the taskbar or the system tray), the Search tab lists the documents, the first one is selected with its preview, and the folder browsers sync to it as with the sync button - even when the button is off. Paths that aren't indexed documents are reported; only the indexed folders are accessible.
  * The help on connecting AI assistants (preferences: 'How to connect AI assistants (Claude, ChatGPT)...') also covers the ChatGPT desktop app and Codex, which share ~/.codex/config.toml ([mcp_servers.docfetcher] with url = "http://localhost:28835/mcp", button to copy it, or 'codex mcp add docfetcher --url ...'), other assistants (HTTP address, or the JSON configuration with mcp-remote), and explains why assistants in the web browser can't connect.
  * MCP tool get_original_document: AI assistants get a copy of the original file (base64 with its MIME type, images that can be shown as an image), e.g. to write a new document in the style of a Word, Excel or PDF file - never access to the file itself. Up to 50 MB (McpMaxOriginalMB in program-conf.txt). Clients built on the MCP SDK read at most 10 MB per message over stdio: the Claude Desktop extension answers larger files with an error message instead of losing the connection.
  * Claude Desktop connects with one file: 'Create Claude Desktop Extension...' in the help on connecting Claude saves docfetcher.mcpb, which is dragged into Claude Desktop (Settings > Extensions). It contains a small bridge to the MCP server on localhost and runs with the Node.js built into Claude Desktop - no Node.js installation, no editing of claude_desktop_config.json. An https address (custom connector) can't work, as Claude Desktop connects those from Anthropic's servers.
  * MCP server: also speaks the stateless protocol revision 2026-07-28 (server/discover, version and client capabilities on every request), next to the earlier revisions 2025-03-26 to 2025-11-25 with initialize - new and older clients connect without version warnings. Unknown versions get 2025-11-25 (was 2025-06-18); resources/list and prompts/list answer with empty lists instead of 'Method not found'; the Claude Desktop configuration uses 'npx -y'.

==== 2026-09-26 - DocFetcher 2.9 ====

=== Bugfixes ===
  * MCP search could take minutes (AI clients gave up): the snippets and the overview read the found documents, and scans without stored text were recognized on the fly. They now use the page text of PDF files without recognition, skip images, and snippets have a time limit of 5 seconds. read_document still recognizes a scan when it is asked for.
  * Storing the recognized text in a file now keeps all its dates - created, modified and accessed - not only the modification date; a PDF converted from a TIFF file gets the dates of the TIFF file.
  * MCP server: documents of indexes with relative paths (portable repositories) could not be read ('Access denied'), and their paths were returned in relative form; paths are normalized now.
  * Switching on the MCP server crashed in the packages (NoClassDefFoundError: the bundled Java runtime lacked the HTTP server module); the runtime now includes it, and a server that can't start only shows a message.
  * The preferences dialog opened slowly while scans were recognized in the background: it waited for the page being recognized (and loaded the text recognition on first use).
  * The MCP port and 'How to connect Claude...' are now right below the MCP option, and the help opens when the server is switched on.
  * Storing the recognized text in a scan no longer starts another update of the whole index: the folder watcher saw the replaced file as a change. DocFetcher now ignores its own changes - but only while the file is exactly as DocFetcher left it, so changes of other files (or of the same file afterwards) are still picked up.

=== Features ===
  * Keys F7 / F8 / F5 (changeable in the preferences, shown in the tab titles, e.g. 'Search (F7)') show the search field, the inbox tabs (again: the next inbox) and the folder browser (with three panes: the middle one). Clicking the Search tab puts the cursor in the search field.
  * The sync button also syncs the search results: the selected document is shown in the rightmost folder browser, the one before it shows the parent folder. Inbox documents don't move the browsers, which keep the folder you are filing into. The separate preference for this is gone, and the button works in all pane modes.
  * MCP read_document gives PDF files in visual order (line by line as on the page), so that labels and values stay together, e.g. in generated rental contracts where the values are drawn after the form ('Grundmiete 620,00 Euro'); order=stream gives the drawing order for pages whose columns get mixed. The index is unchanged.
  * The values of filled PDF form fields are part of the text ('Grundmiete monatlich: 850,00 EUR'), for the search, the preview (an extra page at the end) and AI assistants. Existing indexes parse only their PDF files with filled forms once more on the next update.
  * Excel files (.xls, .xlsx) are indexed with the results of their formulas and the formulas themselves, e.g. '286,52 € [=SUM(B1:B3)]': the search finds totals, and AI assistants see the numbers. Existing indexes parse only their Excel files once more on the next update, no rebuild needed. (program-conf.txt: IndexExcelFormulas = false indexes only the results.)
  * Search words also match the folder names of the path, not only the file name: 'Rosenweg rent' finds a contract in the folder 'Tenants/Rosenweg 12' even if its text doesn't mention 'Rosenweg'; excluded words ('-Rosenweg') exclude such folders. Works at search time with the existing indexes (search settings: 'Also match file and folder names').
  * MCP search: if more documents are found than returned, the newest come first, with an overview (time range, documents per year or month, top folders, characteristic words of the texts - from a sample of up to 20 documents - and of the names, each with the share of documents containing it) and a hint how to narrow the search by adding or excluding words.
  * Preferences: 'How to connect Claude...' below the MCP server options, with buttons to copy the Claude Code command and the Claude Desktop configuration.
  * MCP server for AI assistants (preferences, off by default): assistants like Claude can search the indexes (Google-style query, sorted by date, date range, folder), read the text of documents (in parts of 20,000 characters) and list folders, via http://localhost:28835/mcp. Read-only, only programs on this computer can connect, only the indexed folders are accessible.
  * Remembered answers can be changed and reset in the preferences: 'Ask to rebuild indexes created by older versions' (turned off by 'Don't Ask Again') and the button 'Reset Remembered Answers', which also brings back one-time hints; what happens to the originals after merging or splitting could already be chosen there.

==== 2026-09-21 - DocFetcher 2.4 ====

=== Features ===
  * Text recognition (OCR) with a bundled Tesseract engine (German and English): while indexing, the text of image files (PNG, JPEG, GIF, BMP, TIFF) and of PDF files without text is recognized, so scans can be searched and get name and folder suggestions. PDFs without text get an invisible text layer; PNG and JPEG files keep the recognized text in their metadata. Optionally, TIFF files are converted into PDFs with a text layer (off by default), keeping their fax compression and, if wanted, the original as 'name.tif.ocr'. With 'Store the recognized text in the files' switched off, the text goes into the index only and no file is modified. File dates are preserved. Can be switched off in the preferences. Requires the Microsoft Visual C++ 2015-2022 Redistributable (x64) on Windows.
  * Existing indexes are offered for a one-time rebuild so that scans get recognized.
  * Text recognition runs at the end of an indexing task, after all other documents have been indexed, so they become searchable first.
  * Fixed move targets: folders configured on the new 'Folders' tab of the preferences (which also holds the inbox folders) are always listed first in the 'Move To' menu and in the move dialog.
  * The last five folders you moved files into are offered in the 'Move To' menu and in the move dialog, below the fixed targets.

=== Changes ===
  * The result and inbox tables show the file name in the first column instead of the title; the separate 'Filename' column is gone.
  * The 'Path' column became 'Folder' and no longer repeats the file name; the full path is shown as a tooltip and in the status bar, and the column can be switched off in the preferences.
  * Indexing progress: a progress bar at the bottom right of the main window shows the overall progress of all queued indexing tasks, and the 'Indexes' tab of the preferences has a 'Status' column (queued, creating/updating/rebuilding with percentage, time of the last update).
  * Index management and settings are reachable from the menu bar only; the 'Manage Indexes' entry of the search-scope context menu was removed. Clicking the progress indicator in the status bar (or double-clicking an index with a running task on the 'Indexes' tab) shows the indexing window, e.g. to press 'Run' for a new index.
  * Search results whose files have been deleted or moved in the meantime are no longer shown; the affected index is updated in the background. Optionally, all indexes are updated once a day while the program runs (on by default).

=== Bugfixes ===
  * Files whose names contain accented characters in decomposed form (e.g. synced from macOS or written by some apps) were reported as "File not found" in the preview and couldn't be renamed or moved.
  * The preview of Word documents saved by newer Word versions failed with "string value 'start' is not a valid enumeration value for ST_Jc".
  * Text recognition of some archive TIFF files (fax compression) threw an ArrayIndexOutOfBoundsException; such files are now decoded with the bundled Leptonica library, and recognition errors no longer interrupt indexing.
  * The preview of TIFF files failed for many files; TIFFs are now decoded like in text recognition, and multi-page TIFFs can be browsed page by page.
